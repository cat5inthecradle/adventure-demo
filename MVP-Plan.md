# MVP Plan — The Accessible Space Adventure

A tiny, deterministic text-adventure engine where an LLM is an *optional* language
interface, never a game master. This plan is written so that each task can be handed
to a smaller AI model (or a junior developer) and implemented independently, in order.

Source pitch: `pitch.md`. Core invariant, repeated everywhere it matters:

> **The LLM may understand what the player means, but it never gets to decide what is true.**

---

## 1. Decision log (settled — do not revisit during implementation)

| Decision | Choice | Rationale |
|---|---|---|
| Language / stack | Python 3.12+, Pydantic v2 | Reliably generated by small models; Pydantic validates every schema boundary |
| World content | JSON data files, validated at load | Engine/content separation; testable, swappable worlds |
| LLM layer | Anthropic API behind an `NLUProvider` interface | `client.messages.parse()` with a Pydantic schema guarantees structured output; local models can be added later as another provider |
| Default NLU model | `claude-opus-4-8`, overridable via `--model` / `ANTHROPIC_MODEL` | Sensible default; the user can choose e.g. `claude-haiku-4-5` for cheaper/faster NLU |
| Architecture | Engine as pure library emitting typed **events**; thin CLI REPL frontend | Modality independence: text/speech/braille renderers all consume the same events |
| State mutation | `apply(world, action)` mutates the world **in place** and returns events | Simpler than persistent data structures; save/load provides snapshots |
| Persistence | Serialize the entire `WorldState` model to JSON | One model = one save file; trivially correct |
| Meta commands (save/load/quit/help) | Handled by the CLI, not the engine | Engine actions only ever mutate world state |
| Testing | pytest; no network in any test (Anthropic client is mocked) | Deterministic CI |
| Dependencies | Runtime: `pydantic>=2.7`, `anthropic` (only imported when LLM enabled). Dev: `pytest` | Minimal surface for implementer models |

## 2. Architecture overview

```
                 player input (text)
                        │
              ┌─────────▼──────────┐
              │      cli.py        │  REPL, meta commands, input routing
              └──┬──────────────┬──┘
       (terse)   │              │   (natural language, optional)
        ┌────────▼───┐    ┌─────▼──────────┐
        │ parser.py  │    │    nlu.py      │  NLUProvider → Anthropic API
        │ (dumb,     │    │ utterance →    │  returns Action OR a
        │  offline)  │    │ Action/clarify │  clarifying question
        └────────┬───┘    └─────┬──────────┘
                 │   Action     │   Action
              ┌──▼──────────────▼──┐
              │     engine.py      │  validates legality, mutates WorldState,
              │  apply(world, a)   │  returns list[Event]   ← ONLY source of truth
              └─────────┬──────────┘
                        │  list[Event]  (typed, no prose formatting decisions)
              ┌─────────▼──────────┐
              │    renderer.py     │  Event → text (speech/braille renderers later)
              └────────────────────┘
```

Data flow rules (enforce these in review):

1. **Only `engine.apply()` mutates `WorldState`.** Parser, NLU, renderer, and CLI never do.
2. **The parser and NLU produce `Action` objects referencing entity IDs** (never free text).
   They resolve names → IDs but do not check legality — the engine does.
3. **Events carry structured data + content strings copied from world data.** The renderer
   formats them into prose; it never invents facts.
4. **No I/O, no randomness, no clock access** in `models`, `engine`, `parser`, `renderer`,
   `queries`, `events`, `actions`. All I/O lives in `cli.py`, `persistence.py`, `loader.py`
   (file reads), and `nlu.py` (network).

## 4. Conventions for implementer agents

- Python 3.12+. Full type hints on every function signature.
- Pydantic v2 idioms only: `model_validate`, `model_dump`, `model_dump_json`,
  `TypeAdapter` for unions. Never Pydantic v1 (`parse_obj`, `.dict()`).
- Entity IDs are `snake_case` strings, unique across ALL entity kinds (rooms, doors,
  items, NPCs share one ID namespace — the loader enforces this).
- Every user-visible string comes from either world JSON or a renderer template.
  No prose literals in `engine.py`.
- After completing a task, run `pytest -q` from the repo root; all tests must pass.
- Do not change the data contracts in section 5 without updating this plan file.
- Keep functions small; no clever metaprogramming — a smaller model must be able to
  read and extend every file.

## 5. Data contracts (authoritative — implement exactly)

### 5.1 `models.py`

```python
from typing import Literal
from pydantic import BaseModel, Field

Direction = Literal["north", "south", "east", "west", "up", "down"]

# Special location values for Item.location (besides room IDs):
LOC_INVENTORY = "inventory"   # carried by the player
LOC_HIDDEN = "hidden"         # not in the world (not yet revealed, or consumed)

class Exit(BaseModel):
    to: str                       # destination room id
    door_id: str | None = None    # if set, this exit passes through a Door

class Door(BaseModel):
    id: str
    name: str
    aliases: list[str] = Field(default_factory=list)
    description: str
    open: bool = False
    locked: bool = False
    unlock_flag: str | None = None    # opening succeeds only when this flag is True
    locked_message: str | None = None # narration when opening fails while locked

class Item(BaseModel):
    id: str
    name: str
    aliases: list[str] = Field(default_factory=list)
    description: str
    location: str                     # room id | "inventory" | "hidden"
    portable: bool = True
    alt_description: str | None = None  # used instead of description when...
    alt_flag: str | None = None         # ...world.flags.get(alt_flag) is True

class Effect(BaseModel):
    """One world mutation. Discriminated by `type`."""
    type: Literal["set_flag", "move_item", "set_door", "win_game"]
    # set_flag:
    flag: str | None = None
    value: bool | None = None
    # move_item:
    item_id: str | None = None
    to: str | None = None             # room id | "inventory" | "hidden"
    # set_door:
    door_id: str | None = None
    open: bool | None = None
    locked: bool | None = None
    # win_game: no extra fields (win text lives on the Interaction/DialogueRule message)

class DialogueRule(BaseModel):
    requires_flags: dict[str, bool] = Field(default_factory=dict)
    text: str
    effects: list[Effect] = Field(default_factory=list)
    once: bool = False
    fired: bool = False               # mutable state, persisted in saves

class NPC(BaseModel):
    id: str
    name: str
    aliases: list[str] = Field(default_factory=list)
    description: str
    location: str                     # room id
    dialogue: list[DialogueRule]      # evaluated top to bottom; first match wins

class Room(BaseModel):
    id: str
    name: str
    description: str
    exits: dict[Direction, Exit] = Field(default_factory=dict)
    alt_description: str | None = None
    alt_flag: str | None = None

class Interaction(BaseModel):
    """A 'use X [on Y]' rule."""
    id: str
    item_id: str                      # the item being used (must be in inventory or room)
    target_id: str | None = None      # item, NPC, or door id; None = "use X" bare
    requires_flags: dict[str, bool] = Field(default_factory=dict)
    message: str                      # narration on success
    effects: list[Effect] = Field(default_factory=list)
    once: bool = False
    fired: bool = False               # mutable state, persisted in saves

class WorldState(BaseModel):
    schema_version: int = 1
    title: str
    intro: str
    win_epilogue: str                 # printed after the GameWon event text
    player_location: str              # room id
    rooms: dict[str, Room]
    doors: dict[str, Door] = Field(default_factory=dict)
    items: dict[str, Item] = Field(default_factory=dict)
    npcs: dict[str, NPC] = Field(default_factory=dict)
    interactions: list[Interaction] = Field(default_factory=list)
    flags: dict[str, bool] = Field(default_factory=dict)
    won: bool = False
    turn_count: int = 0
```

Note: `requires_flags` compares against `world.flags.get(name, False)` — an absent flag
counts as `False`, so `{"droid_active": false}` matches a fresh world.

from typing import Annotated, Literal, Union

    type: Literal["take"] = "take"

    type: Literal["drop"] = "drop"

    type: Literal["open"] = "open"

    type: Literal["use"] = "use"

### 5.3 `events.py`

```python
from enum import StrEnum
from typing import Annotated, Literal, Union
from pydantic import BaseModel, Field

class Reason(StrEnum):
    NO_EXIT = "no_exit"                 # no exit in that direction
    DOOR_CLOSED = "door_closed"         # exit exists but door is shut
    DOOR_LOCKED = "door_locked"         # open attempt failed; door is locked
    ALREADY_OPEN = "already_open"
    NOT_PRESENT = "not_present"         # entity not visible here
    NOT_PORTABLE = "not_portable"
    ALREADY_CARRYING = "already_carrying"
    NOT_CARRYING = "not_carrying"       # drop target not in inventory
    NOT_OPENABLE = "not_openable"       # open target isn't a door
    NOTHING_HAPPENS = "nothing_happens" # no matching interaction / dialogue
    GAME_OVER = "game_over"             # action after the game is won

class EntityRef(BaseModel):
    id: str
    name: str

class ExitView(BaseModel):
    direction: str
    door: EntityRef | None = None
    door_open: bool | None = None       # None when there is no door

class RoomDescribed(BaseModel):
    type: Literal["room_described"] = "room_described"
    room: EntityRef
    description: str                    # already alt-resolved by the engine
    exits: list[ExitView]
    items: list[EntityRef]              # visible items in the room
    npcs: list[EntityRef]

class EntityExamined(BaseModel):
    type: Literal["entity_examined"] = "entity_examined"
    entity: EntityRef
    description: str                    # already alt-resolved

class Moved(BaseModel):
    type: Literal["moved"] = "moved"
    from_room: EntityRef
    to_room: EntityRef

class ItemTaken(BaseModel):
    type: Literal["item_taken"] = "item_taken"
    item: EntityRef

class ItemDropped(BaseModel):
    type: Literal["item_dropped"] = "item_dropped"
    item: EntityRef

class DoorOpened(BaseModel):
    type: Literal["door_opened"] = "door_opened"
    door: EntityRef

class ItemUsed(BaseModel):
    type: Literal["item_used"] = "item_used"
    item: EntityRef
    target: EntityRef | None
    message: str                        # Interaction.message

class NpcSpoke(BaseModel):
    type: Literal["npc_spoke"] = "npc_spoke"
    npc: EntityRef
    text: str                           # DialogueRule.text

class InventoryListed(BaseModel):
    type: Literal["inventory_listed"] = "inventory_listed"
    items: list[EntityRef]

class GameWon(BaseModel):
    type: Literal["game_won"] = "game_won"
    epilogue: str                       # WorldState.win_epilogue

class ActionFailed(BaseModel):
    type: Literal["action_failed"] = "action_failed"
    reason: Reason
    subject: EntityRef | None = None    # the entity involved, when known
    message: str | None = None          # world-supplied override (e.g. locked_message)

Event = Annotated[
    Union[RoomDescribed, EntityExamined, Moved, ItemTaken, ItemDropped, DoorOpened,
          ItemUsed, NpcSpoke, InventoryListed, GameWon, ActionFailed],
    Field(discriminator="type"),
]
```

### 5.4 World JSON format

A world file is exactly a serialized `WorldState` with the runtime fields at their
defaults (`won: false`, `turn_count: 0`, `fired: false` everywhere). `rooms`, `doors`,
`items`, `npcs` are JSON objects keyed by ID; each value repeats its `id` field (the
loader verifies key == value.id). See section 7 for the full Wayfarer example.

### T2 — Loader, queries, and test fixtures

**Goal:** load world JSON with strict referential-integrity checks, plus the pure
read-only helpers every other module uses.

**Files:** `loader.py`, `queries.py`, `tests/fixtures/tiny_world.json`,
`tests/fixtures/invalid/*.json`, `tests/test_loader.py`.

**Spec — `loader.py`:**
```python
class WorldValidationError(Exception):
    """Raised with a human-readable message naming the offending entity."""

def load_world(path: str | Path) -> WorldState: ...
def validate_world(world: WorldState) -> None: ...   # raises WorldValidationError
```
`validate_world` checks, in order (first failure raises with a message naming the IDs):
1. Every dict key equals its value's `id` (rooms, doors, items, npcs).
2. All IDs are unique across rooms ∪ doors ∪ items ∪ npcs.
3. `player_location` is a room ID.
4. Every `Exit.to` is a room ID; every `Exit.door_id` is a door ID.
5. Every door referenced by an exit exists, and every door is referenced by at least
   one exit (orphan doors are an error).
6. Every `Item.location` is a room ID, `"inventory"`, or `"hidden"`.
7. Every `NPC.location` is a room ID.
8. Every `Interaction.item_id` is an item ID; every non-None `target_id` is an
   item, NPC, or door ID; interaction `id`s are unique.
9. Every `Effect` names entities that exist (`item_id` → items, `door_id` → doors)
   and has the fields its `type` requires (`set_flag` needs `flag`+`value`;
   `move_item` needs `item_id`+`to`; `set_door` needs `door_id` and at least one of
   `open`/`locked`; `win_game` needs nothing). Check effects inside interactions
   AND inside npc dialogue rules.
10. `schema_version == 1`.

**Spec — `queries.py`** (all pure functions, no mutation):
```python
def current_room(world: WorldState) -> Room: ...
def items_in_room(world: WorldState, room_id: str) -> list[Item]: ...
def npcs_in_room(world: WorldState, room_id: str) -> list[NPC]: ...
def inventory(world: WorldState) -> list[Item]: ...
def doors_in_room(world: WorldState, room_id: str) -> list[Door]:
    """Doors attached to any exit of the room, deduplicated, in exit order."""
def visible_entities(world: WorldState) -> list[Item | NPC | Door]:
    """Everything the player can currently refer to:
    items in the current room + inventory + NPCs here + doors here."""
def find_entity(world: WorldState, entity_id: str) -> Item | NPC | Door | Room | None: ...
def entity_ref(entity) -> EntityRef: ...     # (id, name) helper
def resolved_description(world: WorldState, obj: Item | Room) -> str:
    """alt_description if alt_flag is set and truthy in world.flags, else description."""
def flags_match(world: WorldState, required: dict[str, bool]) -> bool: ...
```

**Fixture — `tiny_world.json`:** 2 rooms (`room_a` start, `room_b` east of it through
door `door_ab`, which starts open... make it: closed and unlocked), items `rock`
(portable, in room_a, alias `["stone"]`), `statue` (non-portable, room_a), `gem`
(hidden), npc `robot` in room_b with two dialogue rules (a `once` rule requiring
`{"greeted": false}` that sets `greeted=true`, then a catch-all), one interaction
`use rock on statue` → message + effects `move_item gem -> room_a` and
`set_flag statue_hit=true`, and one interaction `use gem` (no target) → `win_game`.
`win_epilogue`: any short string. This fixture exercises every mechanic and is reused
by T3–T6 tests.

**Fixtures — `invalid/`:** copies of tiny_world each with exactly one defect:
`bad_exit_target.json`, `orphan_door.json`, `duplicate_id.json`,
`bad_item_location.json`, `interaction_missing_item.json`, `effect_missing_field.json`.

**Tests:** tiny_world loads; each invalid file raises `WorldValidationError` whose
message contains the offending ID; `visible_entities` on the fresh tiny world returns
rock, statue, door_ab (and nothing from room_b).

**Acceptance:** all loader tests pass.

### T3 — Engine

**Goal:** the single source of truth: `apply(world, action) -> list[Event]`.

**Files:** `engine.py`, `tests/test_engine.py`.

**Spec:**
```python
def apply(world: WorldState, action: Action) -> list[Event]:
    """Validate legality, mutate world in place, return events. Deterministic.
    No I/O. Never raises for illegal player actions — returns ActionFailed."""

def describe_room(world: WorldState) -> RoomDescribed:
    """Build the RoomDescribed event for the current room (used by apply(Look)
    and by the CLI at game start / after load)."""
```

Behavior table (implement each row; emit events in the order listed):

| Action | Legality checks (first failure → `ActionFailed(reason, subject)`) | On success: mutation + events |
|---|---|---|
| `Look` | — | `[describe_room(world)]` |
| `Examine(target)` | target in `visible_entities` else `NOT_PRESENT` | `[EntityExamined]` with `resolved_description` (doors/NPCs use plain `description`) |
| `Go(direction)` | exit exists else `NO_EXIT`; if exit has a door: door.open else `DOOR_CLOSED` (subject=door) | set `player_location`; `[Moved, describe_room(world)]` |
| `Take(item)` | item is in current room else (`ALREADY_CARRYING` if in inventory, else `NOT_PRESENT`); `portable` else `NOT_PORTABLE` | item.location = "inventory"; `[ItemTaken]` |
| `Drop(item)` | item in inventory else `NOT_CARRYING` | item.location = current room; `[ItemDropped]` |
| `Open(target)` | target is a door in `doors_in_room` else `NOT_OPENABLE` (or `NOT_PRESENT` if it's not here); not already open else `ALREADY_OPEN`; if `door.locked` and not (unlock_flag set and truthy) → `DOOR_LOCKED` with `message=door.locked_message` | if it was locked but unlock_flag is now truthy: set `locked=False`; set `open=True`; `[DoorOpened]` |
| `Use(item, target)` | item in inventory or current room else `NOT_PRESENT`; target (if given) in `visible_entities` else `NOT_PRESENT`; find first `Interaction` matching `(item_id, target_id)` with `flags_match(requires_flags)` and `not (once and fired)` — none found → `NOTHING_HAPPENS` | mark `fired=True`; apply effects in order; `[ItemUsed(message=...)]` + `[GameWon]` last if a `win_game` effect ran |
| `Talk(npc)` | npc in current room else `NOT_PRESENT`; first `DialogueRule` with `flags_match` and `not (once and fired)` — none → `NOTHING_HAPPENS` | mark `fired=True`; apply effects; `[NpcSpoke(text=...)]` + `[GameWon]` if a `win_game` effect ran |
| `ShowInventory` | — | `[InventoryListed]` |

Cross-cutting rules:
- If `world.won` is already `True`, every action returns `[ActionFailed(GAME_OVER)]`.
- Increment `world.turn_count` once per `apply` call that does **not** return an
  `ActionFailed` as its only event.
- Effect application (private `def _apply_effect(world, effect) -> bool` returning
  whether it was `win_game`): `set_flag` → `world.flags[flag] = value`;
  `move_item` → `world.items[item_id].location = to`; `set_door` → assign the
  provided fields; `win_game` → `world.won = True` (the caller appends
  `GameWon(epilogue=world.win_epilogue)` after the ItemUsed/NpcSpoke event).
- `describe_room`: description via `resolved_description`; exits sorted in the fixed
  order north, south, east, west, up, down; items exclude non-visible ones (there is
  no invisibility flag in v1 — all items whose location is this room are listed);
  door state included in `ExitView`.

**Tests (`test_engine.py`)** — load tiny_world fresh in each test:
- One test per table row's success path.
- One test per `Reason` value (all 11 must be produced by some scenario;
  `GAME_OVER` via winning first, then acting).
- Closed door blocks `Go`; opening it then allows `Go`.
- `use rock on statue` reveals gem in room; second use → `NOTHING_HAPPENS` only if
  the fixture marks it `once: true` (make it `once: true`).
- Talking to robot twice: first fires the once-rule and sets the flag; second gets
  the catch-all.
- `use gem` (after revealing and taking it) → `ItemUsed` then `GameWon`, `world.won`.
- Determinism: applying the same scripted action list to two fresh loads yields
  identical `model_dump()` world states and identical event lists.

**Acceptance:** engine tests pass; no `print`/file access anywhere in `engine.py`.

### T4 — Command parser

**Goal:** the deliberately dumb, offline parser: text → `Action` or a structured error.

**Files:** `parser.py`, `tests/test_parser.py`.

**Spec:**
```python
from dataclasses import dataclass

@dataclass
class ParseError:
    kind: Literal["empty", "unknown_verb", "unknown_noun", "ambiguous", "missing_noun"]
    verb: str | None = None
    noun: str | None = None
    candidates: list[EntityRef] | None = None   # for "ambiguous"

def parse(world: WorldState, text: str) -> Action | ParseError: ...
```

Normalization: lowercase; strip punctuation (`.,!?'"`); split on whitespace; drop
articles and filler tokens `{"the", "a", "an", "to", "at", "on", "in", "with", "up",
"that", "this"}` (the demonstratives are required by T9's "grab that battery" case)
**after** verb-phrase matching (so "talk to droid" and "pick up cell" work — match the
multi-word verb phrase first, then strip fillers from the remainder).

Grammar (verb phrase → action; longest phrase matches first):

| Verb phrases | Action | Remainder |
|---|---|---|
| `look`, `l` | `Look` | must be empty (else treat as examine) |
| `look at X`, `look X`, `examine X`, `x X`, `inspect X`, `read X` | `Examine` | X = noun |
| `go D`, `walk D`, `move D`, `head D`, or bare `D`/initial (`north`/`n`, `south`/`s`, `east`/`e`, `west`/`w`, `up`/`u`, `down`/`d`) | `Go` | D = direction |
| `take X`, `get X`, `grab X`, `pick up X` | `Take` | X = noun |
| `drop X`, `put down X` | `Drop` | X = noun |
| `open X` | `Open` | X = noun |
| `use X on Y`, `use X with Y`, `put X in Y`, `insert X in/into Y`, `give X to Y` | `Use` | X, Y split on the preposition |
| `use X`, `pull X`, `push X`, `press X` | `Use` (target None) | X = noun |
| `talk to X`, `talk X`, `speak to X`, `ask X` | `Talk` | X = noun |
| `inventory`, `i`, `inv` | `ShowInventory` | — |

Noun resolution (`_resolve(world, tokens) -> str | ParseError`), scope =
`visible_entities(world)` (which already includes inventory):
1. Exact match: the joined phrase equals a candidate's `name.lower()` or any alias.
2. Else token-subset match: every phrase token appears in the candidate's
   name+aliases token set (so "cell" or "power cell" matches "glowing power cell",
   and "battery" matches via alias).
3. Zero matches → `ParseError("unknown_noun")`. Two+ → `ParseError("ambiguous",
   candidates=[...])`.

Unknown first token → `ParseError("unknown_verb", verb=token)`. Verb with empty
remainder where a noun is required → `ParseError("missing_noun", verb=...)`.
The parser never checks legality (a visible but non-portable item still parses into
`Take` — the engine rejects it).

**Tests:** table-driven, ≥30 cases covering every grammar row, every synonym at least
once, both resolution modes, `ambiguous` (add a second "small rock" item to a
test-local copy of tiny_world), `unknown_verb`, `unknown_noun`, `missing_noun`,
`empty`, and case/article insensitivity ("TAKE THE ROCK!").

**Acceptance:** parser tests pass.

### T10 — NLU interface + fake provider

**Goal:** the language-interface contract, with a deterministic fake for tests —
no network code yet.

**Files:** `nlu.py` (partial), `tests/test_nlu.py` (partial).

**Spec:**
```python
class NLUContext(BaseModel):
    """A constrained snapshot of what the player can currently see/do.
    This is ALL the model gets — it cannot reference anything else."""
    room_name: str
    room_description: str
    exits: list[str]                        # directions
    visible: list[NLUEntity]                # id, name, aliases, kind
    inventory: list[NLUEntity]
    legal_action_types: list[str]           # ["look","examine","go",...]

class NLUEntity(BaseModel):
    id: str
    name: str
    aliases: list[str]
    kind: Literal["item", "npc", "door"]

class NLUResolution(BaseModel):
    kind: Literal["action"] = "action"
    action: Action

class NLUClarification(BaseModel):
    kind: Literal["clarify"] = "clarify"
    question: str

class NLUUnavailable(BaseModel):
    kind: Literal["unavailable"] = "unavailable"
    detail: str

NLUResult = NLUResolution | NLUClarification | NLUUnavailable

class NLUProvider(Protocol):
    def resolve(self, utterance: str, context: NLUContext,
                transcript: list[tuple[str, str]]) -> NLUResult: ...
        # transcript: last few (player_line, game_response) pairs, oldest first

def build_context(world: WorldState) -> NLUContext: ...   # uses queries.py only

def validate_resolution(world: WorldState, action: Action) -> Action | None:
    """Defense in depth: every entity id the action references must be in
    build_context(world)'s visible+inventory sets (directions must be current
    exits for Go). Returns the action if clean, None otherwise. The engine
    still has the final say on legality even for actions that pass."""
```

### T11 — Anthropic NLU provider + CLI integration

**Goal:** the real language layer. Natural sentences become validated actions;
ambiguity becomes a question; the deterministic engine remains the only authority.

**Files:** `nlu.py` (complete), `cli.py` (extend), `tests/test_nlu.py` (extend).

**Spec — `AnthropicNLU`:**

The structured-output response schema (flat on purpose — most robust to generate):
```python
class NLUWireResponse(BaseModel):
    result: Literal["action", "clarify"]
    # when result == "action":
    action_type: Literal["look", "examine", "go", "take", "drop",
                         "open", "use", "talk", "inventory"] | None = None
    direction: Direction | None = None      # for "go"
    entity_id: str | None = None            # examine/take/drop/open/talk target, or the used item
    target_id: str | None = None            # for "use ... on ..."
    # when result == "clarify":
    question: str | None = None
```

```python
class AnthropicNLU:
    def __init__(self, model: str = "claude-opus-4-8", client: anthropic.Anthropic | None = None):
        self._client = client or anthropic.Anthropic()   # reads ANTHROPIC_API_KEY / ant profile
        self._model = model

    def resolve(self, utterance, context, transcript) -> NLUResult:
        ...
```
The call (this exact shape — `parse` validates against the Pydantic schema
server-side, so the model structurally cannot free-text):
```python
response = self._client.messages.parse(
    model=self._model,
    max_tokens=1024,
    system=SYSTEM_PROMPT,
    messages=[{"role": "user", "content": self._format_request(utterance, context, transcript)}],
    output_format=NLUWireResponse,
)
wire = response.parsed_output   # NLUWireResponse | None
```

`SYSTEM_PROMPT` (module constant, verbatim):
```
You translate a player's natural-language input into ONE structured command for a
text adventure game. You are an interpreter, not a game master: you never decide
outcomes, never invent objects, and never describe the world.

Rules:
- entity_id and target_id MUST be copied exactly from the ids listed in the game
  state you are given. Never invent an id.
- Choose the single command that best matches the player's intent.
- If the input is ambiguous between two or more visible entities, or references
  something not in the lists, or asks for something no command expresses, return
  result="clarify" with one short question offering the concrete options.
- If the player asks a question about their surroundings ("what's around me?",
  "where am I?"), return the "look" action. If they ask about a specific visible
  thing, return "examine" for it.
- Prefer "clarify" over guessing.
```

`_format_request` renders the utterance, then the context as labeled plain-text
sections (ROOM, EXITS, VISIBLE with `id — name (aliases)` lines, INVENTORY,
COMMANDS), then up to the last 4 transcript pairs under RECENT.

Mapping `NLUWireResponse → NLUResult` (`_to_result`):
- `result == "clarify"` → `NLUClarification(question or "Could you rephrase that?")`.
- `result == "action"` → construct the matching `Action` (`entity_id` fills the
  single-entity field; `use` uses `entity_id`+`target_id`). Missing required fields,
  or `validate_resolution(world_action)` returning None → fall back to
  `NLUClarification("I couldn't match that to anything here — what did you mean?")`.
  (Pass the needed context into `_to_result` via the already-built `NLUContext`;
  `validate_resolution` is refactored in this task to take an `NLUContext` instead
  of a `WorldState` so `nlu.py` needs no world access.)
- Any `anthropic.APIError` / `anthropic.APIConnectionError`, or `parsed_output is
  None` → `NLUUnavailable(detail=str(exc))`. **Never raise out of `resolve`.**

**Spec — CLI integration:**
- New flags: `--llm {auto,on,off}` (default `auto`), `--model` (default
  `claude-opus-4-8`, env override `ANTHROPIC_MODEL`).
  `auto`: enable iff `ANTHROPIC_API_KEY` is set; `on`: always construct the provider
  (the SDK also resolves `ant auth login` profiles); `off`: never.
- Input routing per line (after meta commands): run the parser first. If it returns
  an `Action`, use it (terse commands stay instant and offline). If it returns a
  `ParseError` and NLU is enabled, call `nlu.resolve(line, build_context(world),
  transcript)`:
  - `NLUResolution` → apply via the engine as usual.
  - `NLUClarification` → print the question; the next input line is handled
    normally (the transcript gives the model the context to interpret the answer).
  - `NLUUnavailable` → print "The language assistant is unavailable
    ({short detail}). Classic commands still work — type 'help'." and fall back to
    `render_parse_error` for this line.
  If NLU is disabled, just `render_parse_error`.
- Maintain `transcript: list[tuple[str, str]]` of the last 6 (player line, rendered
  response) pairs; append after every turn including clarifications.
- Print an LLM status line at startup: "Language assistant: on ({model})" / "off".
