# Adventure Lab: teacher guide

A suggested 60-minute lesson about what AI may interpret, write, and change. Learners play a small adventure, inspect its rules, compare AI capabilities, author one object, and explain a boundary for real-life apps. No prior coding is required. The timing below is a planning target; adjust it after observing your learners.

## Before class

- Open the lesson on representative classroom devices and check that the command field, inspector, and authoring form fit. A laptop, Chromebook, or tablet with a keyboard is preferable to a phone for this lesson.
- If using live AI, choose a model in the AI Interpreter menu and wait for the ready indicator. Try a short request and an impossible request. Check the network policy and available storage before asking a whole class to download models. Model sizes are shown in the menu.
- A model may be unavailable, slow, or unreliable even when the app works. Test **Use recorded examples** on Levels 3 and 4 as the alternative; it needs no model download or WebGPU. The base game and object editor also work without AI.
- Use **Reset lesson** between independent test runs or learners sharing a browser. Read its confirmation: it clears lesson answers, objects, progress, and challenge work across all worlds. It retains downloaded models and named game saves. Restarting a game only restarts that game.
- Use fictional game content. The app stores lesson work locally in the browser. Names are not required in the app; the printed card has an optional blank name line. Follow your organization's normal process before classroom research or sharing exported work.

## A flexible hour

- **0–5 minutes: introduce the question.** What should AI be allowed to do, and who decides whether its output changes something real? Choose a world and explain how to ask for help.
- **5–15 minutes: play and look inside (Levels 1–2).** Solve the small puzzle. Examine the story detail that is not an object, then inspect the command. If time is tight, use the progressive hints or Next to move on; unfinished work remains visible on the card.
- **15–30 minutes: investigate AI (Levels 3–4).** Compare requests, a rejected proposal, generated scenery, and invented dialogue. Use live results, recorded examples, or a mixture. Save observations separately from a preferred dial setting. Two unhelpful replies still support a comparison; success must not depend on getting a particular model answer.
- **30–40 minutes: make something real (Level 5).** Add the missing object, write its description, and test it. Discuss the difference between describing an object and defining it in the game.
- **40–50 minutes: apply the idea (Level 6).** Choose a capability for each app and explain a consequence. Compare the capability's meaning with the reason. A concise reason is enough; different choices invite discussion rather than automatic grading.
- **50–60 minutes: debrief and share.** Review or print the AI rules card. Discuss one observation and one boundary. Early finishers can begin a challenge sooner; learners needing more time can skip all extensions.

## Help without taking over

**Need a hint?** first reminds learners of the goal. **Give me a clue** names a relevant object or action. **Show the next command** reveals an exact next step only when requested. Hints update as the puzzle changes, including after picking up or dropping an object.

Ask “What did you expect?” and “What evidence did you see?” before supplying a solution. A refused action can be useful evidence. The inspector shows a short explanation first; Details contains the action, rules, and world changes. A convincing description or an empty inventory alone does not establish whether an object exists.

For keyboard navigation, focus a command and press Enter to inspect it. The navigation buttons also move directly to command entry, the latest inspector, or lesson instructions. Their shortcuts are Alt+C, Alt+I, and Alt+L while focus is in the lesson. On Mac keyboards, Alt is Option. If a system intercepts a shortcut, use the visible buttons. Level changes move focus to the lesson instructions.

## Optional investigations

All challenges use separate practice copies and can be left with **Back to my lesson**. Positions, applied edits, notes, and self-checks save locally; command history lasts for the current visit. Model reuse is an explicit choice. Core lesson answers and the authored core object are preserved.

- **Test the interpreter — about 5–8 minutes.** Compare three wordings and an impossible request; explain an unexpected result. Recorded examples are available.
- **Make your object foolproof — about 5–10 minutes.** Test two aliases and a pickup rule; revise using an unexpected input or partner feedback.
- **Investigate The Wayfarer — about 10–15 minutes.** Find two clues, solve one dependency, and inspect an interpretation. Finishing the game is optional.

These durations describe content capacity, not measured engagement. No challenge is required for lesson completion.

## Debrief and the card

- Which words came from an author, the game rules, or AI? How did you check?
- What did the game prevent an AI proposal from doing? Could a useful request also be refused?
- When did generated words sound like a fact that the rules did not support?
- What changed when you authored the object yourself?
- In one real-life app, what may AI do, what happens if it is wrong, and who should check?

The card includes a compact completion account, live/recorded routes, saved observations and one example's evidence, the authored object and pickup rule, and scenario choices with reasons. **Preview my card** is available even with unfinished work. Completion labels describe activities, not demonstrated mastery. Discuss missing or contradictory reasoning rather than treating the card as an automatic assessment.

Long cards may use more than one page. In print preview, confirm the final real-life reason and footer are present before printing. Use the card's Print button; the game interface is omitted from the printed version.
